## 二、冻结接口契约（改动前必须公告）

| `getCheckinTimestamp() → "YYYY.MM.DD HH:mm"` | B | photoSynthesizer |

## 三、跨模块数据结构契约

### 3.1 `guide` 对象（A 主责，B/C 消费）

现有字段全部为冻结项，B 的 `MissionPanel` 和 C 的 `App.jsx` 均直接使用：

```js
{
  key,            // "xiaoling"|"lingruo"|"xingyuan"|"dongling"|"wailing" —— localStorage 依赖，禁止改
  name,           // 显示名
  englishName,
  image,          // "/assets/xxx.webp" —— 路径规范见 5.3
  thumbnail,
  trait, voiceLabel, emotion,
  rate, pitch, volume,          // 语音参数（useSpeech 消费）
  voiceHintsZh: [], voiceHintsEn: [],
  preview, welcome
}
```

**注意**：`useSpeech.js` 第 13 行硬编码了 `guide.key === "dongling"` 的特殊处理，改 key 名会静默破坏语音节奏。

### 3.2 `route` 对象（C 主责，A 消费）

A 的 `AssistantPanel` 把 `route` 传给 `resolveAnswer(question, route, language)`，以下字段为冻结项：

```js
{
  title,        // 字符串（2026-10-18 起由「兴趣偏好 → 节奏」推导，不再沿用基础路线固定文案）
  reason,       // 字符串（personalizeRoute 会重写）
  duration,     // "半日游"/"1日游"/"2日游"/"3日游" 等字符串
  distance,     // "5.2km"
  comfort,      // 数字（RoutePanel 渲染进度条）
  days,         // 🆕 数字：1/2/3（多日行程天数）
  pace,         // 🆕 "轻松休闲"|"适中游览"|"深度体验"
  budget,       // 🆕 "¥100以下"|"¥100-300"|"¥300-500"|"¥500以上"
  perks,        // 🆕 字符串数组：该预算包含的服务（RoutePanel 展示「预算内含」）
  steps: [ [地名, 描述, "HH:mm", 第几天], ... ]  // 🆕 四元组数组；第 4 位为新增的天序号，前三位含义不变
}
```

**C 改 steps 结构（如改成对象数组）前必须通知 A**，否则知识库问答引用路线站点时会拿到 undefined。

> **2026-10-18 变更（待 A 确认）**：`steps` 由三元组扩展为四元组，新增的第 4 位为天序号。已核对 A 的 `knowledge.js:99` 仅取 `step[0]`，**当前不受影响**；但提示词或工具中若有按下标取值的写法需一并检查。前三位含义与顺序未变，属向后兼容扩展。

### 3.3 `profile` 对象（C 产出 → App 消费）

```js
{
  age,          // "青少年"|"大学生"|"中年"|"银发"|"中老年"|"老年人"…（chooseRoute 内有硬编码年龄映射表，❄）
  companion,    // "独自"|"朋友"|"亲子"|"团队"
  interests: [],  // 含 "摄影打卡"、"亲子研学" 等关键词，chooseRoute 按关键词匹配，❄
  fitness,      // "轻松优先"|…
  time,         // "2"|"4"|"6"|"8"
  language,     // "中文"|其他 → 决定英文模式
  access,       // "暂无"|其他 → 非空则强制 accessible 路线

  // 🆕 2026-10-18：主界面「定制你的专属路线」面板产出（constraints），旧字段全部可缺省
  duration,     // "half"|"1d"|"2d"|"3d"
  interests,    // 数组，四选一：["文化祈福"|"自然风光"|"亲子游"|"摄影打卡"]，可为空数组
  budget,       // "under100"|"100-300"|"300-500"|"above500"
  pace          // "relaxed"|"moderate"|"deep"
}
```

> 该枚举值被 `chooseRoute()`（routes.js:150-157）和 `personalizeRoute()` 的映射表硬编码，**C 自己改也要先全量检查**，A 的智能体提示词里同样引用这些画像字段。

> **2026-10-18 新增**：`duration/interests/budget/pace` 四项为新面板画像。优先级：`access` → `language` → **`interests`（兴趣偏好命中即定路线）** → 旧画像兜底。四种取值与 `agentTools.recommend_route` 的入参枚举一一对应，**改任一取值必须同步 A 的 `agentConfig.js`**。

### 3.4 `checkinBackgrounds[i]` 对象（B 独占，但数组下标有全局含义）

```js
{
  id,           // "zhaobi"|"jiulong"|"fangong"|"dafou"
  title, description,
  gradient,     // CSS 渐变字符串（photoSynthesizer 解析）
  overlayText, overlaySubtext, icon,
  decorations: [{ type: "stamp"|"date"|"watermark"|"pattern"|"completion", text?, position }]
}
```

**数组下标 = 打卡点序号**，与 App.jsx 的 `missions` 状态一一对应（见 4.2）。

### 3.5 `missions` 状态（C 在 App.jsx 持有，B 消费）

// 布尔数组，长度必须 === checkinBackgrounds.length（当前 4）

### 3.6 消息对象（A 内部，但 AdminDashboard 若做"对话审计"会消费）

### 3.7 `scenicSpots[i]` 景点对象（C 主责，路线 / 地图 / 智能体共用）

```js
{
  id,                      // 唯一 key（React key 用 name-index 组合，改 id 不影响）
  name, en, aliases: [],   // ❄ 站名归一化的唯一入口：findSpot() 靠这三组匹配
  x, y,                    // ❄ 相对地图的百分比坐标 → 地图编号节点与矢量路线按此定位
  category, stay,          // 类别 + 建议停留分钟数：时间轴「建议停留 X 分钟 · 类别」与站点档案卡消费
  tagline, intro,          // 副标题与介绍正文
  highlights: [],          // 看点标签数组
  note,                    // 「数字人建议」的实时提示文案
  order                    // 推荐环线序号，buildStops 据此排序，保证路线不来回折返
}
```

九个景点：灵山大佛、梵宫、祥符禅寺、五印坛城、百子戏弥勒、九龙灌浴、香水海、灵山照壁、灵山蔬食馆。

> **强约束 1**：`route.steps` 的站名必须能被 `findSpot()` 命中。
> - 命中 → 地图画出该站、编号与景点对齐、站点档案卡与「数字人建议」正常展示；
> - 未命中 → `toPoint()` 返回 `null`，该节点与整段路线不渲染；若当前站未命中，`.spot-profile` 档案卡会条件性消失（连带卡片底部吸收余量的锚点丢失）。
> - 因此 **A 调整人设提示词 / 工具定义导致输出站名变化时，需先确认新站名落在 `name` / `en` / `aliases` 覆盖范围内**。

> **强约束 2**：`x` / `y` 是百分比，`MAP_WIDTH` / `MAP_HEIGHT`（现 987 × 552）、`.scenic-map` 的 `aspect-ratio`、素材 `scenic-map.webp` 的真实比例**三者必须一致**，否则编号节点会漂移。详见 4.6。
