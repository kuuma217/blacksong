## 二、冻结接口契约（改动前必须公告）

### 2.1 导出函数签名（❄ 不可单方面更改）

| 签名 | 归属 | 消费方 |
|---|---|---|
| `callAgent(guideKey, userMessage, conversationHistory = [], options = {}) → Promise<{content, source, fallback, ...}>` | A | AssistantPanel（A 自用），但**返回对象中 `fallback`、`content` 字段名不得改** |
| `isAgentAvailable() → boolean` | A | AssistantPanel |
| `resolveAnswer(question, route, language = "zh") → {answer, source, ...}` | A | AssistantPanel；**`route` 参数是跨模块依赖，字段契约见 3.2** |
| `synthesizeCheckinPhoto({ userImage, background, width = 800, height = 1000 }) → Promise<string /* DataURL */>` | B | MissionPanel；**参数对象字段名不得改** |
| `getBackgroundByIndex(index) → background 配置对象` | B | MissionPanel |
| `getCheckinTimestamp() → "YYYY.MM.DD HH:mm"` | B | photoSynthesizer |
| `chooseRoute(profile) → routeKey /* "photo"\|"culture"\|"senior"\|"family"\|"international"\|"accessible" */` | C | App.jsx |
| `personalizeRoute(routeKey, profile) → route 对象` | C | App.jsx；**route 对象字段契约见 3.2** |
| `useSpeech() → { speaking, listening, speak, startListening }` | A | AssistantPanel（A 自用）；**返回值仅此四项，`voices`/语音停止逻辑为内部实现，不可直接引用**；若 B 需要语音能力，调用此 Hook，不得另写一套 |

### 2.2 导出数据对象（❄ 结构冻结，新增字段允许，删改字段禁止）

| 导出 | 归属 | 消费方 |
|---|---|---|
| `guides`（`{ key → guide对象 }`）+ `guideList` | A（主责） | App.jsx（C 用 `guides[guideKey]` 传给 MissionPanel）、AssistantPanel |
| `agentConfig`、`agentSystemPrompts`、`agentTools` | A | A 自用 + AdminDashboard（C）展示模型设置时读取 |
| `checkinBackgrounds`（数组，**当前长度 = 4**） | B | photoSynthesizer、MissionPanel |
| `routeCatalog` | C | C 自用，但 App 的 `routeKey` 初始值 `"photo"` 引用了 key `"photo"`，**key 名不得改** |
| `knowledgeBase` | A | A 自用 |

### 2.3 组件 Props（❄ 由 App.jsx 调用，新增 props 须经 C 同意并同步修改 App.jsx）

## 三、跨模块数据结构契约

### 3.1 `guide` 对象（A 主责，B/C 消费）

现有字段全部为冻结项，B 的 `MissionPanel` 和 C 的 `App.jsx` 均直接使用：

```js
{
  key,            // "xiaoling"|"lingruo"|"xingyuan"|"dongling"|"wailing" —— localStorage 依赖，禁止改
  name,           // 显示名
  englishName,
  image,          // "/assets/xxx.webp" —— 路径规范见 5.3
  thumbnail,
  trait, voiceLabel, emotion,
  rate, pitch, volume,          // 语音参数（useSpeech 消费）
  voiceHintsZh: [], voiceHintsEn: [],
  preview, welcome
}
```

**注意**：`useSpeech.js` 第 13 行硬编码了 `guide.key === "dongling"` 的特殊处理，改 key 名会静默破坏语音节奏。

### 3.2 `route` 对象（C 主责，A 消费）

A 的 `AssistantPanel` 把 `route` 传给 `resolveAnswer(question, route, language)`，以下字段为冻结项：

```js
{
  title,        // 字符串
  reason,       // 字符串（personalizeRoute 会重写）
  duration,     // "4小时" 等字符串
  distance,     // "5.2km"
  comfort,      // 数字（RoutePanel 渲染进度条）
  steps: [ [地名, 描述, "HH:mm"], ... ]  // 三元组数组，下标固定
}
```

**C 改 steps 结构（如改成对象数组）前必须通知 A**，否则知识库问答引用路线站点时会拿到 undefined。

### 3.3 `profile` 对象（C 产出 → App 消费）

```js
{
  age,          // "青少年"|"大学生"|"中年"|"银发"|"中老年"|"老年人"…（chooseRoute 内有硬编码年龄映射表，❄）
  companion,    // "独自"|"朋友"|"亲子"|"团队"
  interests: [],  // 含 "摄影打卡"、"亲子研学" 等关键词，chooseRoute 按关键词匹配，❄
  fitness,      // "轻松优先"|…
  time,         // "2"|"4"|"6"|"8"
  language,     // "中文"|其他 → 决定英文模式
  access        // "暂无"|其他 → 非空则强制 accessible 路线
}
```

> 该枚举值被 `chooseRoute()`（routes.js:150-157）和 `personalizeRoute()` 的映射表硬编码，**C 自己改也要先全量检查**，A 的智能体提示词里同样引用这些画像字段。

### 3.4 `checkinBackgrounds[i]` 对象（B 独占，但数组下标有全局含义）

```js
{
  id,           // "zhaobi"|"jiulong"|"fangong"|"dafou"
  title, description,
  gradient,     // CSS 渐变字符串（photoSynthesizer 解析）
  overlayText, overlaySubtext, icon,
  decorations: [{ type: "stamp"|"date"|"watermark"|"pattern"|"completion", text?, position }]
}
```

**数组下标 = 打卡点序号**，与 App.jsx 的 `missions` 状态一一对应（见 4.2）。

### 3.5 `missions` 状态（C 在 App.jsx 持有，B 消费）

```js
const [missions, setMissions] = useState([true, false, false, false]);
// 布尔数组，长度必须 === checkinBackgrounds.length（当前 4）
// 下标含义：0 照壁已预完成，1→九龙灌浴，2→梵宫，3→大佛
```

**B 增删打卡点时：** 同步修改 `App.jsx:35` 初始值 → 该改动必须由 C 执行；且新打卡点的 `id`、背景图文件名需发群公告。

### 3.6 消息对象（A 内部，但 AdminDashboard 若做"对话审计"会消费）

```js
{ id, role: "user"|"guide", text, source?, emotion? }
```

## 四、隐式契约（最易踩坑，全部冻结）

### 4.1 localStorage Key（❄ 只准 C 动）

| Key | 写入方 | 读取方 |
|---|---|---|
| `lingjing-guide` | App.jsx | App.jsx 初始化 `guideKey` |
| `lingjing-route` | App.jsx | App.jsx 初始化 `routeKey` |
| `lingjing-route-profile` | App.jsx | App.jsx 初始化 `routeProfile`（JSON） |

改 key = 用户本地数据全部丢失，且三处必须同时改。

### 4.2 环境变量（❄ 只准 A 动）

`VITE_QWEN_API_KEY`、`VITE_QWEN_API_URL`、`VITE_QWEN_MODEL`。
`.env.local` **永不提交**（VITE_ 前缀变量会被打进前端构建产物，仓库里也不留 Key）。新环境变量统一在 `.env.example` 登记。

### 4.3 `notify` 通知函数（App.jsx 定义，三方共用）

```js
notify(message, type = "success")  // type: "success" | "info" | "error"
```

只调用、不改实现；新增 type 需 C 同步改 `ToastHost`。

### 4.4 素材路径约定（❄）

- 数字人形象：`/assets/{key}.webp`、`/assets/{key}-thumb.webp`（guides.js 引用）；
- 数字人装扮素材：`/assets/{key}-lotus.webp`、`-night.webp`、`-sunset.webp`（MissionPanel 的衣橱功能按 guides key 拼路径消费，**改一个数字人 key = 连带 5 个素材文件名**）；
- 打卡背景当前使用纯渐变 + 文字，无图片依赖；若 B 引入图片，统一放 `public/assets/checkin/`，命名 `checkin-{id}.webp`；
- **任何新增/改名 `public/` 下的文件必须群公告**，因为字符串路径散落在 data 文件里，重构工具无法追踪。

### 4.5 分支与产物

- 分支：`feat/agent`（A）、`feat/checkin`（B）、`feat/route-admin`（C），主干 `main` 只接受合并；
- `02_Windows可执行程序/www` 是构建产物，**禁止手工修改**；发版时由 C 执行 `npm run build` 后整体替换；
- `dist/`、`node_modules/`、`.env.local` 必须在 `.gitignore` 中（已配置）；`www/` 是交付产物**保留在仓库**，但禁止手工修改，发版由 C 整体替换。

## 五、需要统一的方面（全队一致，违反 = Code Review 打回）

### 5.1 代码风格（三人统一按现有代码为准）
- 组件默认导出 `export default function X()`，数据/工具具名导出，**不得混用**；
- 组件文件 PascalCase（`AssistantPanel.jsx`），工具/数据文件 camelCase（`agentConfig.js`）；
- JSX 双引号、JS 字符串双引号、缩进 2 空格、分号齐全 —— 与现有源码保持一致；
- 不引入新依赖：当前仅 `react`、`react-dom`、`gsap`、`ogl`、`vite`、`@vitejs/plugin-react`；如需新增（如图表库），向 C 提需求，由 C 统一安装并锁定。

### 5.2 注释与命名
- 对外导出的函数必须写 JSDoc（参数 + 返回值），格式参照 `photoSynthesizer.js` 现有注释；
- localStorage key、环境变量、打卡点 id 等字符串常量沿用 `lingjing-` 前缀命名法；
- 注释用中文，写"为什么"而不是"是什么"。

### 5.3 素材管理
- 图片统一 WebP（照片类）/ PNG（UI 类），单图 ≤ 300KB；
- 命名：`{模块}-{名称}-{尺寸?}.webp`，全小写连字符；
- 删除素材前必须全局搜引用并通知所有人。

### 5.4 CSS 归属
- 组件样式只写在组件同目录 `.css`；全局样式（主题色、布局变量）只写 `src/styles.css`（C 管）；
- 禁止在组件 css 里覆盖他人组件的 class；`!important` 原则上禁止；
- 新增全局 class 前缀：`assistant-`、`mission-`、`route-`、`admin-` 按模块隔离。

### 5.5 Git 流程
- 提交信息：`feat(agent): xxx` / `fix(mission): xxx` / `style(admin): xxx`，模块名固定为 `agent` / `mission` / `route` / `admin` / `core`；
- 每日下班前各分支合并一次 `main`（小步合并，别攒大招）；
- 冲突解决原则：**接口契约文档说了算**；文档没写的，找归属人当面确认，不猜。

### 5.6 验收基线（合并前自查）
1. `npm run build` 无报错（等价于 `npm run check`）；
2. 无 API Key 时功能正常（智能体自动降级到本地知识库，不是报错）；
3. 自己模块涉及 localStorage 的读写不抛异常（隐私模式下也正常）；
4. 管理后台账号 `admin / lingjing2026` 能登录（演示用，禁止改）。

## 六、并行修改冲突防控（红绿灯机制）

> 三人同时改功能时，合并失败几乎都发生在"共享文件"上。规则：**先看灯，再动手。**

### 6.1 权限等级定义

| 灯 | 含义 | 操作要求 |
|---|---|---|
| 🟢 自由区 | 你独占的文件 | 直接改，无需打招呼 |
| 🟡 公告区 | 别人在消费的文件 / 共享数据 | 改前群里发一句"我要改 XX 的 XX"，得到消费方"收到"即可动手 |
| 🔴 禁改区 | 归属人不是你 / 全局枢纽 | 自己不动手，提需求给归属人，由归属人改 |

### 6.2 A 的红绿灯

| 文件 | 权限 |
|---|---|
| `agentConfig.js`、`knowledge.js`、`AssistantPanel.jsx`、`useSpeech.js`、`.env.example`、`assistant-*.css` | 🟢 自由区 |
| `guides.js` | 🟡 公告区（加字段可直接改；**改/删字段**先通知 B、C） |
| `App.jsx`、`ToastHost`、`SpecularButton` 等公共 UI、`styles.css`、`package.json` | 🔴 禁改区 → 提需求给 C |
| 其余所有文件 | 🔴 禁改区 |

### 6.3 B 的红绿灯

| 文件 | 权限 |
|---|---|
| `photoSynthesizer.js`、`MissionPanel.jsx`、`CheckinPreviewModal.jsx`、`checkinBackgrounds.js`、`mission-*.css`、`public/assets/checkin/*` 新增 | 🟢 自由区 |
| `checkinBackgrounds` 数组长度变化、打卡点 `id` 变化 | 🟡 公告区（同步 C 改 App.jsx 的 missions 初始值） |
| `guides.js`（只读消费）、`App.jsx`、公共 UI、`styles.css` | 🔴 禁改区 → 提需求给 A（guides）/ C（其他） |

### 6.4 C 的红绿灯

| 文件 | 权限 |
|---|---|
| `App.jsx`、`routes.js`、`RoutePanel.jsx`、`ProfileModal.jsx`、`AdminDashboard.jsx`、`LoginModal.jsx`、`Header.jsx`、`main.jsx`、`styles.css`、公共 UI 原子组件、`index.html`、`vite.config.js`、`package.json/.lock`、`route-*.css`、`admin-*.css` | 🟢 自由区 |
| `App.jsx` 中引用 A/B 模块 props 的传参行 | 🟡 公告区（改了传哪个 prop，必须通知对应消费方） |
| `guides.js`、`agentConfig.js`、B 的四个打卡文件 | 🔴 禁改区 → 提需求给 A / B |

### 6.5 冲突高发点与针对性防控

**① App.jsx（最高危）** —— 三方功能的接线板，人人都需要加 props/状态：

- 短期规则（立即执行）：A/B **一律不直接编辑**，需要新状态/新 props 时在群里按模板提需求：`【接线需求】模块 / 需要的 state 或 props / 用途`，由 C 当天完成接线；
- 中期优化（建议 C 尽早做）：把 `missions`、`routeProfile` 等状态抽到 `src/hooks/useMissions.js`、`useRouteProfile.js`，让各模块自带自己的状态，App.jsx 只剩组装，三方共改面积趋近于零；
- 兜底：C 每天合并主干时如遇 App.jsx 冲突，**以主干为准 + 手工叠加三方接线**，不得简单选边。

**② `styles.css` 全局样式** —— 只准 C 改；A/B 需要新全局样式（主题色、间距变量）提需求。各自组件样式一律写在组件同目录 css，class 加模块前缀（`assistant-` / `mission-` / `route-` / `admin-`），前缀内改样式不算冲突。

**③ 页面/新功能新增** —— 随意建新组件文件（新文件永远不冲突），但：文件名带模块前缀（如 `AssistantQuickReply.jsx`）；新页面接线进 `App.jsx` 走 ① 的流程。

**④ 素材文件** —— 新增 🟢；改名/删除 🔴（必须先全局搜引用 + 群公告）。

**⑤ 依赖与配置** —— `package.json`、`vite.config.js`、`index.html` 只准 C，杜绝三方各自装包导致 lock 文件冲突。

### 6.6 合并节奏与冲突解决阶梯

- **每天下班前**：各分支 `git pull main` → 解决小冲突 → 跑 `npm run build` → 合回 `main`。小步快合，绝不攒到周末；
- **大改前**（重构某模块、动 🟡 公告区文件）：开工前先 rebase 最新主干；
- **冲突解决顺序**：本契约文档 → 归属人当面确认 → 仍无结论则三方语音会议，15 分钟内定案；
- **禁止**：`git push -f`、跳过 `npm run build` 直接合并、悄悄改 🟡/🔴 文件。
